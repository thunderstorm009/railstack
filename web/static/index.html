ReliStack

A three-service Docker Compose stack — NGINX reverse proxy, Flask API, Redis cache — built to be broken on purpose. Every component has a healthcheck, a restart policy and a documented failure mode.

Live status

Proxy checking

GET /healthz on the NGINX container itself.

API checking

GET /api/hello through the proxy to the Flask container.

Cache checking

GET /api/count round-trips through Redis.

What this stack demonstrates

Health-gated startup

depends_on: service_healthy — a service starts only after its dependency actually answers.

Explicit restart policies

unless-stopped for the front door, on-failure:5 for the API.

Graceful vs forced shutdown

stop sends SIGTERM, kill sends SIGKILL. The exit codes differ: 143 vs 137.

Persistent storage

A named volume keeps the Redis counter alive across down — but not across down -v.

Try it

curl -s http://localhost:8080/healthz
curl -s http://localhost:8080/api/hello
curl -s http://localhost:8080/api/count

Break it (on purpose)

./scripts/chaos.sh kill-api        # SIGKILL the API, watch the proxy 502
./scripts/chaos.sh crash-api       # crash-loop until retries are exhausted
./scripts/chaos.sh oom-api         # exceed the memory limit, watch exit 137
./scripts/chaos.sh bad-config      # break nginx.conf, watch the fail-fast entrypoint
./scripts/chaos.sh recover         # bring the stack back to green
